# Этап 1: как запустить BuildOS

Код первого этапа уже записан в проект. Интерфейс теперь работает через серверные API с настоящей PostgreSQL. Старые данные localStorage не используются как база; в браузере остаются только тема, язык и временный флаг демо-входа.

## Что уже подготовлено

- Модули компании, тендеров, проектов, стройплощадки, закупок, AI и рабочего пространства.
- Prisma Client и схема со связями между компаниями, пользователями и проектами.
- SQL-миграции, индексы и ограничения данных.
- Демо-данные: Build Group, шесть ролей, тендер Alatau на ₸8.5 млрд. Вторая компания нужна для проверки изоляции.
- API с проверкой JSON, UUID, ролей, дат, статусов, email, фото и размеров запросов.
- Общая обработка ошибок с HTTP-статусами и requestId.
- Сохранение операций в базе и транзакции для преобразования тендера и создания заявки.
- Unit- и интеграционные тесты.

## 1. Откройте терминал в папке проекта

```powershell
cd C:\Users\mikur\Desktop\buildos
```

Нужен Node.js 20.9+; на этом компьютере используется Node.js 24. Зависимости уже установлены. После копирования проекта на другой компьютер:

```powershell
npm ci
npm run env:setup
```

Команда env:setup создаёт `.env` со случайным локальным паролем, если файла ещё нет. Существующий `.env` она не меняет. Пароли не выводятся в терминал. `.env` и файлы базы исключены из Git.

## 2. Запустите PostgreSQL — выберите один способ

### Способ А: локальная база без Docker

В проект включён инструмент локального PostgreSQL 16. Он запускает настоящую PostgreSQL, а не замену или имитацию. Файлы хранятся в `.data/postgres`, доступ разрешён только через 127.0.0.1. Он не устанавливает службы Windows и не создаёт системные учётные записи.

В первом терминале:

```powershell
npm run db:local
```

Дождитесь `PostgreSQL 16 ready on 127.0.0.1:55432`. Оставьте этот терминал открытым. Ctrl+C останавливает базу, данные сохраняются.

Если порт уже занят, команда не пытается завершить чужой процесс. Если это уже запущенная база BuildOS, продолжайте со второго терминала. Если это другой процесс, выберите свободный порт в `.env`: обновите и `POSTGRES_PORT`, и порт в `DATABASE_URL`. При первом запуске выбранные логин/пароль становятся настройками кластера; изменение пароля в `.env` само по себе пароль существующей базы не меняет.

### Способ Б: Docker

Откройте Docker Desktop и дождитесь готовности Engine. Затем:

```powershell
npm run db:up
```

Compose создаст PostgreSQL 16 и постоянный volume. Порт берётся из `.env`, по умолчанию 55432, и публикуется только на 127.0.0.1. Остановка без удаления данных:

```powershell
npm run db:down
```

Не запускайте оба способа на одном порту. Это два разных хранилища, их данные автоматически не переносятся. На этом компьютере для проверки использован способ А: Docker Engine не был доступен.

### Способ В: установленная или внешняя PostgreSQL

Укажите своё подключение в `.env`:

```dotenv
DATABASE_URL="postgresql://USER:PASSWORD@HOST:PORT/buildos?schema=public"
DEMO_MODE=true
DEMO_COMPANY_ID=10000000-0000-4000-8000-000000000001
```

Создайте пустую базу buildos. Пароль со специальными символами в URL нужно кодировать. Команды db:local и db:up при этом не нужны.

## 3. Подготовьте схему и начальные данные

Во втором терминале, в той же папке:

```powershell
npm run db:prepare
```

Команда последовательно:

1. Генерирует Prisma Client — типизированный клиент базы.
2. Применяет сохранённые SQL-миграции через migrate deploy.
3. Выполняет seed — создаёт демо-компании, пользователей и тендеры.

Повторный seed не удаляет данные и не сбрасывает проекты. На этом компьютере схема и seed уже применены. Команда db:setup — сокращённый вариант для Docker, объединяющий env:setup, запуск контейнера и db:prepare.

## 4. Запустите приложение

В том же втором терминале:

```powershell
npm run dev
```

Откройте http://localhost:3000. Проверка состояния базы: http://localhost:3000/api/health — ожидается `status: ok`.

Демо-вход пока принимает любой корректный email и пароль от шести символов. Выбранная роль служит для демонстрации. Настоящие сессии, регистрация и приглашения будут реализованы на втором этапе. Не размещайте этот режим в открытом доступе.

## 5. Проверьте сохранение

1. Войдите как директор. В тендерах должен быть Alatau или ранее сохранённые записи.
2. Нажмите «Проанализировать тендер».
3. Нажмите «Отметить победу → Создать проект».
4. Проверьте блок А, два этажа и зоны.
5. Создайте дефект и ежедневный отчёт.
6. Создайте заявку из AI-рекомендации.
7. Перезагрузите страницу: данные сохранятся в PostgreSQL.
8. Перезапустите Next.js: бизнес-данные останутся.

AI-анализ всё ещё mock, как допускает ТЗ. Он не читает содержимое PDF или фотографий. Документы сохраняют метаданные и номера версий, а загрузка бинарных файлов относится к следующим этапам.

## 6. Команды проверки

```powershell
npm test
npm run test:integration
npm run typecheck
npm run db:validate
npm run build
```

При работающем Next.js можно выполнить `npm run test:smoke`: он проверяет реальные HTTP-ответы, доступность базы и отклонение подмены компании/состояния. По умолчанию используется http://127.0.0.1:3000; для другого адреса задайте BUILDOS_URL.

Unit-тестам база не нужна. Интеграционным тестам нужен работающий PostgreSQL с применёнными миграциями; они создают случайные тестовые компании, проверяют процессы и удаляют только свои записи. Проверки покрывают конкурентное преобразование тендера, заявки и версии документов, сохранение после переподключения и запрет связей между компаниями.

Просмотр базы с GUI:

```powershell
npm run db:studio
```

## 7. Как изменять модели дальше

1. Измените `prisma/schema.prisma`.
2. В разработке выполните `npm run db:migrate -- --name название_изменения`.
3. Сохраните созданную папку миграции вместе с кодом.
4. На следующем окружении примените `npm run db:deploy`.

Начальные миграции после применения не редактируйте. Используйте новую миграцию. CHECK-ограничения поддерживаются отдельным SQL: Prisma 6 не описывает их в schema.prisma. `db:migrate` использует теневую базу; локальный пользователь для разработки имеет необходимые права.

## Если что-то не запускается

| Ошибка | Что делать |
|---|---|
| CONFIGURATION_ERROR | Проверьте `.env` и DATABASE_URL. |
| DATABASE_UNAVAILABLE | Запустите db:local или Docker; проверьте порт и пароль. |
| SCHEMA_NOT_READY | Выполните db:prepare. |
| AUTH_REQUIRED | Для локального этапа нужен DEMO_MODE=true. |
| FORBIDDEN | Выберите роль, которой разрешено это действие. |
| VALIDATION_ERROR | Проверьте обязательные поля и формат данных. |
| Порт 3000 занят | Next.js предложит другой порт, смотрите вывод dev. |
| Port 55432 is occupied | Используйте уже запущенную базу BuildOS либо выберите свободный порт. |

Не удаляйте `.data/postgres` или Docker volume ради исправления ошибки: там находятся данные. При смене пароля, версии PostgreSQL или способа запуска сначала сделайте резервную копию.
