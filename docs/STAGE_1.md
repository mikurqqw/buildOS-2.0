# Первый этап: результат

Этап «Основа приложения» реализован в коде и проверен на локальной PostgreSQL 16.

| Требование | Результат |
|---|---|
| Разделение на модули | Company, tenders, projects, field, procurement, AI, workspace; общие DTO и серверная инфраструктура |
| PostgreSQL + Prisma | Реальное чтение/запись, один Prisma Client, конфигурация .env |
| Миграции | Начальная схема и отдельная SQL-миграция CHECK-ограничений |
| Валидация | Zod, строгие структуры команд, UUID, даты, email, статусы и лимиты |
| Обработка ошибок | HTTP-статусы, стабильный envelope, requestId, безопасные сообщения |
| Начальные данные | Две компании, шесть ролей в каждой, тендеры; повторный seed не стирает данные |
| Подключение интерфейса | Общий API-клиент, загрузка из PostgreSQL, localStorage только для предпочтений и демо-флага |
| Транзакции | Тендер → проект, риск → заявка, нумерация версий |
| Проверки | Unit-тесты, интеграционный сценарий на PostgreSQL, TypeScript, Prisma, сборка |

## Что проверить пользователю

Проверено 10.10.2026: 11 unit-тестов, интеграционный сценарий на PostgreSQL 16, HTTP smoke (главная страница, readiness, данные компании, отклонение подмены tenant/state), TypeScript и Prisma validation. Миграции применены, повторный seed успешно выполнен. Интеграционные тесты дополнительно проверили CHECK-ограничения и выключение демо-доступа. Компонент выбора роли/статуса проверяется во всех трёх языках: отображаемый перевод не меняет значение формы.

1. Запустить базу и Next.js по SETUP_RU.md.
2. Пройти путь от тендера до заявки.
3. Перезагрузить страницу и убедиться в сохранении данных.
4. Проверить переключение темы и языка.

## Что не входит в первый этап

Настоящая авторизация и проверенные роли, безопасный внешне доступный SaaS, отправка приглашений, загрузка бинарных документов, приём/закрытие дефектов, полный цикл согласования закупок, реальные AI-модели, отдельные ролевые аналитические панели и офлайн-синхронизация. Эти функции остаются в следующих этапах исходного ТЗ.

Текущий демо-контекст нельзя считать защитой от входа другого человека: роль выбирается клиентом, а компания фиксирована серверной настройкой. Следующий этап — регистрация компаний, сессии и membership/RBAC для чтения и записи.

## Известные ограничения среды и зависимостей

Docker Desktop установлен, но запуск его движка не был надёжно доступен. Для проверки использована собственная локальная PostgreSQL 16 через embedded-postgres, данные внутри `.data/postgres`, порт 55432. Compose сохранён как альтернативный способ запуска.

При установке npm сообщает 12 advisory: 3 moderate и 9 high. Совместимый audit fix не устраняет их; миграцию инструментов нужно выполнить перед внешним развёртыванием. Prisma 6 также сообщает о будущей отмене `package.json#prisma` — на текущей версии конфигурация seed работает. Обновление major-версий не входит в эту инфраструктурную итерацию.
