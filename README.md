# BuildOS MVP

Бесплатное внешнее размещение подготовлено для **Render Free + Neon Free**: [инструкция](docs/FREE_DEPLOY.md). `render.yaml` находится в корне. Новые документы сохраняются в PostgreSQL, поэтому не зависят от временного диска Render. Для публикации нужны вход владельца в эти сервисы и DATABASE_URL в секретных настройках Render; GitHub Pages серверную версию не поддерживает.

Рабочее пространство строительной компании: Next.js 15, React 19, TypeScript, Tailwind, PostgreSQL 16 и Prisma. Русский, казахский и английский; светлая и тёмная темы.

## Запуск

Первый терминал:

```powershell
npm ci
npm run env:setup
npm run db:local
```

Второй терминал:

```powershell
npm run db:prepare
npm run dev
```

Откройте http://127.0.0.1:3000. Зарегистрируйте компанию или войдите по БИН, почте и паролю. Демо-пользователи seed не имеют паролей. Данные сохраняются в PostgreSQL. Docker — альтернативный способ: `npm run db:setup`.

## Что работает

- Регистрация, bcrypt, HttpOnly-сессии, приглашения по ссылке и управление ролями.
- Директор назначает доступ к проектам в `/company`; API проверяет компанию, роль и членство при чтении и записи.
- Семь этапов тендера, редактирование, преобразование в проект. Прежний mock-анализ сохранён, настоящий ИИ пока не подключён.
- Создание и редактирование проектов; свои корпуса, этажи и зоны; изменение и удаление пустых элементов структуры.
- Создание/редактирование задач, сроки, ответственные, приоритеты и связь с дефектами.
- Замечания с фото и местом, проверка исправления другим сотрудником, история статусов.
- Заявки на материалы, согласование/отклонение, заказ, доставка и история решений.
- Реальные файлы PDF/DOCX/XLSX до 10 МБ, версии и защищённое скачивание.
- Операционные сводки по ролям; простая ручная сводка поступлений/выплат для директора и бухгалтера.
- Создание/редактирование ежедневных отчётов; локальные черновики отчётов, новых задач и текстов замечаний.

После миграции директору нужно назначить проекты сотрудникам, кроме директоров и бухгалтеров. Файлы хранятся в `.data/uploads`, локальная база — `.data/postgres`: сохраняйте резервные копии. Старые записи документов без загруженного файла показываются как метаданные.

## Проверки

```powershell
npm test
npm run typecheck
npm run db:validate
npm run test:integration
npm run test:e2e
npm run test:auth
npm run test:company
npm run test:documents
npm run test:workspace
npm run build
```

HTTP-проверкам нужен запущенный сервер. Для Playwright сначала `npx playwright install chromium`; он запускает сервер автоматически, если тот не работает. Скриншоты и трассы тестов содержат только тестовые данные, хранятся локально и не публикуются в Git.

## Текущая граница

[Подробный результат прохода по пунктам 1–10](docs/CHECKPOINT_2026_11_04.md).

Офлайн — черновики на текущем устройстве и ручная отправка после подключения. Полноценного PWA, фоновой синхронизации и сохранения фото в черновиках нет. Повторная отправка отчёта защищена от дублей; задачи и замечания требуют проверки перед повторной отправкой, если ответ сервера потерян.

Это функциональный локальный MVP, не сертифицированная production-система. Сохраняются 6 предупреждений npm audit, не добавлены отдельный линтер, axe и Lighthouse; нужны дальнейшее усиление безопасности и проверка развёртывания. Интеграция ИИ намеренно оставлена отдельным этапом. Публикация исходников на GitHub не является хостингом приложения.
